# Teach and adapt Module 1

Link the [entry page](index.md) directly. Use [Canvas linking guidance](../../instructor/canvas-linking.md) to choose a tested repository commit or a published site route.

## Teach the core first

Start with a prediction or written decision, run the shared implementation, change one input or assumption, and explain the observed result. Use the [foundation bridge](foundation.md) as prerequisite support. The [practice](practice.md) has public [feedback](feedback.md); use these for formative learning. Optional depth is skippable. Pilot pacing with learners before setting deadlines.

The script/text route supports implementation and reasoning; it does not prove notebook-interface operation. If an interface skill is assessed, arrange an effective accessible route. Offer the solo discussion alternative. GenAI is optional; adopting instructors state disclosure and assessment rules.

## Adapt without removing evidence

Retain units, data-origin labels, raw-input preservation, and expected results. Early modules use explicitly labeled teaching fixtures; they are not real incident records. Changing data requires updating the contract, worked feedback, and checks together. Keep master Canvas assessments and private student work outside this repository.

Use the [adaptable assessment guide](../../instructor/assessment.md) for local criteria. A response should identify a decision, reproduce relevant evidence, and explain a limitation; running unchanged code alone is insufficient.

## Accessibility and verification

Use readable code, named outputs, text explanations, and equivalent numerical evidence. Record direct-link reading, execution, modification, saving, and feedback tasks in the [review log](../../accessibility/review-log.md). Automated syntax/behavior/kernel checks do not establish keyboard, screen-reader, zoom, or interface usability.
