# Reusable authoring and review templates

Copy a template, replace all placeholders, and record actual evidence. Templates are also included in the complete source archive. They are authoring aids, not completed review records.

| Template | Use |
| --- | --- |
| [Lesson](../../templates/lesson.md) | Direct-entry learning outcomes, explanation, execution, and checks |
| [Practice](../../templates/practice.md) | Core change, evidence, public feedback, optional depth |
| [Case study](../../templates/case-study.md) | Decision, source rights, shared implementation, evaluation |
| [Instructor adoption](../../templates/instructor-adoption.md) | Local outcomes, semester edition, assessment, access |
| [Accessibility review](../../templates/accessibility-review.md) | Exact task, combination, barrier, repair, retest |
| [Data card](../../templates/data-card.md) | Source, meaning, rights, privacy, transformation, split |
| [Model card](../../templates/model-card.md) | Intended use, identity, observed results, failures, limitations |
| [AI assistance note](../../templates/ai-assistance-log.md) | Bounded assistance and independent verification |

Keep shared behavior in the package. Register new module paths and profiles in curriculum/modules.json. Preserve source rights and meaningful test coverage. The [architecture](../../REPOSITORY_STRUCTURE.md) explains the maintenance boundaries; the [release checklist](../release-checklist.md) separates runtime evidence from pending human review.
