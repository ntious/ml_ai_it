# Teach and adapt

Use one module as additional reading/practice, or adopt its original exercise and rubric. You do not need the original university's Canvas assignments to use this resource.

## Module 3 link card

- Title: Data processing and trustworthy inputs.
- Purpose: validate synthetic network events, document decisions, and interpret quality results.
- Prerequisites: basic functions, data structures, and paths; a foundation bridge is linked from the module.
- Activities: explanation, script or notebook walkthrough, original practice, discussion/reflection, and worked feedback.
- Provisional effort: 45–75 minutes plus setup; pilot with your learners.
- Planned stable entry route: `/lessons/03-data-processing/`, relative to the eventual site base URL. No live site is published by this increment.

Suggested LMS description:

> Additional resource: read Module 3 and run the data-processing example. Use its foundation refresher as needed. The optional extension is for further exploration. Follow this course's assignment and AI-use instructions for any submitted work.

Module numbers need not match your course. Select by topic/outcome. Prefer a tested release when you need stable teaching content.

## Assessment and feedback

The resource's practice is independently authored and includes public worked feedback for self-study. Adapt the criteria to your learners and publish local weights/submission rules if grading it. A solo reflection is available for the discussion concept. Restricted assessment keys and student work should stay outside a public repository.

## AI collaboration

Encourage students to predict, inspect, test, explain, and disclose assistance under your course policy. A useful prompt asks for a critique of a cleaning assumption. Students should verify the response against source data and test outputs. A personal paid AI account is not required for Module 3.

## Accessibility before assigning

Review the [current accessibility status](../accessibility/index.md) and verify the learner's execution route. Avoid requiring screenshots as the only evidence of work; command/output text and source files can demonstrate the same technical decisions. Preserve learning rigor while supporting different interfaces.
