# Worked examples: inspect a real implementation

These cases connect a question, a reviewed source, shared code, evaluation, and a readable result. Run them from the complete source or inspect the generated report first. All examples below use actual external records.

## Forecast historical bike demand

Ask what information is available when tomorrow's forecast is issued. Compare persistence and trained baselines without using future weather or target components as inputs.

[Module 5 lesson](lessons/05-regression/index.md) · [Worked forecast and residual report](downloads/module05/example/index.html)

## Compare classification with clustering

Use real wine chemistry to compare classifiers and decision trees, then examine an unsupervised grouping. Identical chemistry profiles stay within one split. A cluster ID is not a quality rank.

[Module 6 classification](lessons/06-classification/index.md) · [Classifier evidence](downloads/module06/example/index.html) · [Module 7 clustering](lessons/07-clustering/index.md) · [Cluster profiles](downloads/module07/example/index.html)

## Find what SMS accuracy hides

Train a vocabulary and neural classifier on real messages, compare a lexical reference, and inspect actual false negatives. Initial high overall accuracy hid a model that missed every positive in its final sample.

[Module 9 lesson](lessons/09-neural-nlp/index.md) · [Neural NLP evidence](downloads/module09/example/index.html)

## Evaluate local generation and actual tuning

Run the fixed local model against a strict response contract, retain invalid outputs, and inspect a small real adapter update. Tiny tuning is a mechanics demonstration, not a claim of useful production improvement.

[Module 10 generation](lessons/10-llm-workflows/index.md) · [Generation evidence](downloads/module10/example/index.html) · [Module 11 tuning](lessons/11-fine-tuning/index.md) · [Adapter evidence](downloads/module11/example/index.html)

## Connect inference to monitoring

Validate the exact input schema, exercise a local app, and inspect replay over actual held-out records. The static website links the app instructions; the Python app runs locally in the framework environment.

[Module 12 setup and practice](lessons/12-deployment/index.md) · [Monitoring report](downloads/module12/example/index.html)

## Audit decisions and bound tools

Inspect denominators and group evidence from a historic income benchmark. Then trace a model-selected plan whose tools and budget are checked outside the model. Valid tool selection can still misunderstand intent.

[Module 13 fairness](lessons/13-ethics-fairness/index.md) · [Audit evidence](downloads/module13/example/index.html) · [Module 14 bounded agents](lessons/14-agents/index.md) · [Agent trace](downloads/module14/example/index.html)

## Use the evidence responsibly

The examples teach transferable engineering decisions. They do not establish current operational performance, justify decisions about people, or certify a production system. Read the [model-use summaries](model-cards.md), [data rights](data-sources.md), and [access routes](accessibility/index.md).
